# Архитектура MediaHub

Ориентир для проекта — стандартные паттерны Flask: пакет приложения, фабрика `create_app`, отдельные расширения и blueprints по функциям. Такая структура уже есть; копировать крупный шаблон проекта целиком не требуется.

Сейчас `mediahub/__init__.py` собирает приложение и регистрирует blueprints. `config.py` хранит настройки, `database.py` — создание схемы и восстановление прерванных задач, `extensions.py` — объекты расширений. HTTP-маршруты находятся в `auth.py`, `catalog.py`, `admin.py` и `media.py`. `storage.py`, `scanner.py` и `jobs.py` выполняют работу с файлами и фоновые задачи. Шаблоны и статические файлы остаются внутри пакета, тесты — в `tests/`.

При следующем крупном изменении стоит разделить `media.py` (сейчас это самый большой модуль) по функциям: маршруты воспроизведения, подготовка HLS, миниатюры и управление задачами. Сохранять имена blueprint и URL при переносе, чтобы не ломать существующие ссылки и тесты. После этого можно выделить локальное и FTP-хранилище в отдельные адаптеры. Структуру лучше развивать по функциям, а не вводить пустые папки `controllers`, `services` и `repositories` заранее.

Перед изменением схемы SQLite нужна явная система миграций: `db.create_all()` создаёт новые таблицы, но не меняет существующие. Когда появятся учётные записи или история просмотра, стоит добавить Alembic/Flask-Migrate и первую миграцию для уже установленных экземпляров.

`pyproject.toml` задаёт зависимости и правила Ruff, `uv.lock` фиксирует их версии. Для разработки выполняются `uv sync --locked`, `uv run --locked ruff check .`, `uv run --locked ruff format --check .` и `uv run --locked pytest`. Старый Windows-скрипт запуска остаётся на `pip` для совместимости с Windows 8.1.
